# LelekaThoughts для Android

Окремий нативний Flutter-клієнт вебверсії `https://lelekathoughts.vercel.app`, без WebView. Код розташований у `mobile/` гілки `codex/flutter-android`; вебзастосунок залишається в `app/`.

Використовує ту саму Supabase-базу, Auth, Storage, Realtime та `app_action`, що й вебверсія. Акаунт і контент спільні для обох клієнтів. У коді лише публічні ключі; правила доступу перевіряє сервер.

Оновлений [APK 1.0.1, build 3](https://github.com/sekhvolodymyr/LelekaThoughts/releases/tag/android-v1.0.1-preview.2) використовує новий захищений медіашлюз. Попередній APK 1.0.0 потрібно оновити, щоб завантажувати медіа. Після аудиту фонові оновлення об’єднуються й виконуються послідовно, а чат завантажує останні 300 повідомлень без необмеженого Realtime-кешу.

## Можливості

- Стрічки «Для тебе» та «Підписки», підвантаження публікацій, пошук людей, постів, ланцюжків і серій.
- Реєстрація, підтвердження email через сайт, пароль/email або @нік, код на email, відновлення пароля, онбординг від 16 років.
- Пости до 1000 символів і 4 фото; продовження авторських ланцюжків, редагування, видалення, закріплення та цитування.
- Вподобайки, репости, приватне збереження, коментарі й один рівень відповідей.
- Фото та відеосторіс до 30 секунд; постійні серії, прив’язка до ланцюжка та конкретного обговорення, перегляди й вподобайки.
- Публічні профілі, підписки, запити на спілкування, чати з Realtime, лічильники непрочитаного, пересилання постів і серій.
- Груповані сповіщення; скарги, блокування, модерація для серверно призначених адміністраторів.
- Редагування профілю й аватара, інтереси, українська/англійська, світла/темна та чотири градієнтні теми.
- Чернетки тексту локально й у хмарі. Повідомлення та публікації не надсилаються автоматично після повернення мережі.
- Видалення акаунта через наявний захищений серверний endpoint із повторним входом.

## Запуск і збірка

Використано Flutter **3.50.0**, Dart **3.14.0**, JDK **21** (цільова Java 17), Android SDK **36**, NDK **28.2.13676358**, Android Gradle Plugin **9.3.3**. Мінімальна версія Android визначена Flutter-проєктом: API 24 (Android 7.0). Точні залежності зафіксовано в `pubspec.lock`.

AGP оновлений із шаблонного 9.3.1: у [офіційних примітках Android](https://developer.android.com/build/releases/agp-9-3-0-release-notes) описано виправлення збою Lint `java.util.List.removeLast()` у 9.3.2 та подальші виправлення R8 у 9.3.3. Перевірки Android Lint не вимикаються.

```sh
cd mobile
flutter pub get
flutter analyze --no-fatal-infos
flutter test
flutter run
flutter build apk --release
```

APK: `mobile/build/app/outputs/flutter-apk/app-release.apk`. На Windows можна використати `scripts/build-android.ps1`. Flutter SDK, Android SDK, JDK та тимчасові дані збірки не зберігаються у Git.

Для першої встановлюваної збірки використовується локальний тестовий ключ Android. Release-режим оптимізує застосунок; тестовий підпис не є налаштуванням публікації в Google Play. Для власного стабільного production-підпису додайте локальний `android/key.properties` з `storeFile`, `storePassword`, `keyAlias`, `keyPassword`. Файл і keystore виключено з Git; збережіть їх окремо для майбутніх оновлень.

## Google та поштовий вхід

Google-провайдер у спільному Supabase-проєкті поки вимкнений. Застосунок перевіряє це до відкриття браузера й показує повідомлення. Для активації потрібні Client ID / Secret у Supabase, як у вебверсії; не додавайте secret в APK.

Після активації Google додайте до Supabase Redirect URLs:

```text
io.lelekathoughts.app://login-callback
```

В Android manifest уже налаштований intent filter для цієї адреси. Supabase Flutter обробляє PKCE і повернення в застосунок. Google callback у Google Cloud залишається `https://glqsayxjvvnkmhejuqjz.supabase.co/auth/v1/callback`.

Поки для email-підтвердження та відновлення пароля використовується production-сайт. Після підтвердження можна увійти в Android тим самим акаунтом. Доставка email і доступність Google залежать від спільних налаштувань провайдерів; APK не обходить їх. Докладніше: `../app/docs/AUTH-SETUP.md`.

## Перевірка

`test/widget_test.dart` перевіряє шість палітр, контраст, нативний перемикач і збереження вибору.

`integration_test/app_test.dart` запускається на Android-емуляторі. Він перевіряє вхід за @ніком через UI, зміну теми, публікацію через нативний редактор, ланцюжок, завантаження фото, прив’язану серію сторіс, коментарі, підписку, вподобайки, збереження та запит/прийняття чату між двома тестовими акаунтами. Тестові облікові дані передаються лише локально:

```sh
flutter test integration_test/app_test.dart -d emulator-5554 --dart-define-from-file=/private/path/native-qa.json
```

JSON містить `QA_PASSWORD` і `QA_PEER_PASSWORD`; тест очікує акаунти `@leleka_test` і `native.qa.20261114@example.invalid`. Не використовуйте звичайні особисті акаунти для цього сценарію. Секрети й тестові APK із вбудованими `dart-define` не публікуйте. Фінальний APK збирається окремо, без тестових параметрів.

Для кожного повтору потрібен новий тестовий співрозмовник (email можна задати через `QA_PEER_EMAIL`) або попереднє очищення лише чату цієї тестової пари адміністратором. Уже прийнятий чат не повертається в стан запиту самостійно. Тест перевіряє цю передумову й навмисно не видаляє історію листування через клієнтський API.

Google consent, доставка листів зовнішнім отримувачам і фізичні пристрої потребують окремої перевірки після налаштування провайдерів. Відео відтворюється Android-плагіном; сумісність конкретного кодека залежить від пристрою.
