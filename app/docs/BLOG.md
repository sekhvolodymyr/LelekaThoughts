# Мій блог

У вебзастосунку відкрийте «Мій блог» у бічному меню. На телефоні пункт доступний через меню у верхньому лівому куті. Потрібен вхід і завершений профіль із підтвердженим email.

- «Написати статтю»: назва до 160 символів, необов’язковий короткий опис до 240, текст до 50 000 символів. Порожній текст можна зберегти в чернетці, але не опублікувати.
- Текст — звичайний із абзацами. HTML не виконується. Набрані зміни зберігаються на пристрої; «Зберегти чернетку» зберігає їх в акаунті.
- «Опублікувати статтю» відкриває її без реєстрації за `/blog/<uuid>`. Автор може оновити текст, зняти статтю з публікації або видалити.
- Чернетки доступні лише власнику. «Зняти з публікації» також зберігає поточні зміни в чернетці. Старе публічне посилання після цього не відкриває текст.
- Нові статті доступні на `/blog`, посилання на цей розділ є на головній. Опубліковані сторінки мають власні SEO-метадані й BlogPosting JSON-LD; sitemap містить до 1000 останніх публікацій. Публічний список показує 50 останніх; у власному списку доступне підвантаження наступних статей.

Сервер читає статті з правами anon без кешування приватного стану. Тіло статті не передається до публічного списку чи sitemap. RLS закриває чернетки; авторські дії перевіряють auth.uid(), підтвердження email, профіль, вік і власника. Клієнтам не надаються прямі INSERT/UPDATE/DELETE. Реалізація привілейованих дій знаходиться в app_private.blog_dispatch; public.blog_action — обгортка SECURITY INVOKER. Блокування й призупинення профілю враховуються правилами читання. Видалення профілю каскадно видаляє статті.

Розгортання незалежне від неопублікованої монетизації:

1. Після чинних schema.sql/maintenance.sql/hardening.sql застосувати `supabase/migrations/20261116094248_creator_blog.sql`, потім `20261116095128_private_blog_dispatch.sql`.
2. Опублікувати вебінтерфейс, маршрути `/blog`, `/blog/[id]`, sitemap і супровідні CSS/бібліотеки.
3. Перевірити RPC та anon/owner RLS. Локальний тест: `node --import tsx --test scripts/blog-database.test.ts`.

Перевірки реалізації: PGlite SQL/RLS для чернеток, публікації, прав іншого користувача, валідації, блокування, призупинення й видалення; Playwright desktop/mobile з fixture API для редактора; транзакційний прогін RPC в робочій базі з повним rollback. Жодні тестові статті в production не залишаються. Flutter/APK цим оновленням не змінюється.
